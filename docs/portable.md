# LucidDesk 便携版

桌面面板与文件整理 · 开发者 **Yuchen95**

便携包文件名为 `LucidDesk-<版本>-windows-x64-portable.zip`。它通过程序旁的 `portable` 文件启用便携数据目录，适合希望将程序和设置放在一起的用户。主要验证与维护平台为 Windows 11 x64。

## 首次启动

1. 将 ZIP 完整解压到有写入权限的文件夹，不要直接在压缩包内运行。
2. 确认 `luciddesk.exe`、`luciddesk_explorer.dll` 和 `portable` 位于同一目录。
3. 退出已经运行的 LucidDesk，再双击本目录的 `luciddesk.exe`。
4. 首次运行后确认数据目录；没有环境变量覆盖时，程序会在旁边创建 `data`。

重复启动会唤起已有实例，而不是单独打开另一套便携会话。测试或切换版本时先退出旧实例，避免把旧实例的配置误认为本目录的数据。

便携包不需要安装向导，也不自动创建安装版的卸载入口。文件和快捷键操作见[使用说明](usage.md)。Everything、PowerToys Peek 和 QuickLook 需另行安装，相关功能需在设置中启用和配置。

## 文件与数据目录

| 文件或目录 | 用途 |
| --- | --- |
| `luciddesk.exe` | 主程序 |
| `luciddesk_explorer.dll` | 同次构建的桌面组件，必须与主程序配套 |
| `portable` | 便携模式标记，文件名没有扩展名 |
| `data/config.toml` | 使用便携数据路径时的全局配置 |
| `data/workspace.db` | 工作区、布局及其他持久化状态 |
| `data/backups/` | 应用保存的备份 |
| `build.json` | 构建来源、版本和 EXE/DLL 校验值 |

初始发行包不包含个人 `data`。标记的内容不参与模式判断，程序检查的是 EXE 旁是否存在名为 `portable` 的文件。请保留随包标记，不要改成 `portable.txt`，也不要将其替换为同名文件夹。

### 数据路径优先级

| 条件 | 使用的数据目录 |
| --- | --- |
| 已设置 `LUCIDDESK_DATA_DIR` | 该变量指定的目录 |
| 未设置数据目录变量，EXE 旁存在 `portable` 文件 | EXE 旁的 `data` |
| 未设置数据目录变量，且缺少便携标记 | 普通用户数据目录 |

因此，即使标记存在，环境变量仍可使数据保存在程序目录之外。可通过托盘的“打开配置目录”确认当前实际使用位置。默认用户目录规则见[品牌规范](brand.md)。

不要删除标记来尝试恢复或重置配置：这会改变数据路径，并不会迁移原来的 `data`。首次便携启动也不会自动导入 LocalAppData 中的数据。

## 备份与迁移

“设置 → 备份与恢复”可导出和恢复配置、布局。需要从其他发行方式迁移时，先在原实例导出备份，退出后启动便携版，再通过设置恢复；恢复会替换相应状态，不是合并两套布局。

搬移便携目录前，从托盘正常退出并等待组件释放，再复制整个目录，包括 `portable` 与实际使用的 `data`。如果配置被环境变量指向外部目录，仅复制程序文件夹不会带走这些数据。

面板引用的文件、映射文件夹和外部程序仍位于各自原位置。便携数据及应用备份不包含它们的内容；换电脑、盘符或目录后应重新检查文件引用、文件夹映射与预览/搜索程序路径。便携模式不保证所有外部路径自动重定位。

## 更新

1. 在“设置 → 关于”手动检查版本并打开更新页面，下载新版便携 ZIP 及对应 `.sha256`。
2. 核对文件，按需导出当前配置备份。
3. 从托盘退出 LucidDesk，等待主进程和 Explorer 中的桌面组件释放。
4. 解压新版并替换程序文件，保留原 `data` 和便携标记；确认 EXE 与 DLL 来自同一新版。
5. 启动后检查版本、实际数据路径和面板布局。

也可将新版解压到独立目录，在退出旧版后复制原 `data`，再启动验证。不要从运行中的实例复制数据库来代替应用备份，不要只替换 DLL 或混用版本。

应用的更新检查不会自行覆盖程序。安装包会拒绝以包含 `portable` 的目录作为安装目标；需要安装版时使用独立目录，参见[安装说明](installer.md)。

程序直接加载同目录的桌面 DLL。若更新时文件持续占用，确认 LucidDesk 已退出并稍候；仍未释放时可手动重启 Windows 资源管理器或注销后再替换，不要改名旧 DLL 绕过占用检查。

## 校验与移除

ZIP 同目录的 `.sha256` 用于核对下载完整性：

```powershell
Get-FileHash -LiteralPath '<便携 ZIP 完整路径>' -Algorithm SHA256
```

将结果与校验文件中的哈希比较。`build.json` 另记录版本、Git 修订、未提交修改状态和两项二进制哈希，用于核对具体构建；它不替代 ZIP 的校验文件。更新内容见随包的 `CHANGELOG.md` 和 `CHANGELOG.en.md`。

不再使用时，先退出并等待组件释放。保留所需数据或导出备份后，可手动删除便携目录；删除其中的 `data` 会同时删除设置、布局和该目录内的备份。环境变量指定的外部数据不会随程序目录删除，真实桌面文件也不属于便携程序的清理目标。

## 常见问题

| 现象 | 核对方式 |
| --- | --- |
| 启动后看见另一套布局 | 检查旧实例是否仍在运行，再检查标记和数据目录环境变量 |
| 没有生成 `data` | 确认实际启动的 EXE、`portable` 文件名及环境变量覆盖 |
| 配置无法保存 | 确认实际数据目录可写，避免只读介质或受保护目录 |
| 换电脑后文件或预览不可用 | 检查原文件、映射路径及外部程序是否存在；便携包不携带这些内容 |
| 更新无法覆盖 DLL | 退出程序并等待 Explorer 释放组件，不混用其他构建的 DLL |

Windows 10 的用户反馈不代表每个版本都完成验收；ARM64、远程桌面与混合 DPI 需要对应环境验证。报告问题时记录 Windows 构建号、程序版本、实际数据位置、复现步骤与错误提示。


## CLI 与 Agent Skill

主程序旁附带 `luciddesk-cli.exe` 和完整的 `skills/luciddesk-control` 文件夹。使用同一版本的主程序、CLI 和 Skill；更新时一起替换，不要混用。

不使用 Agent 或脚本时，无需配置 CLI。需要连接 Agent 时，在“设置 → 通用 → Agent 与 CLI”复制 Skill 安装提示词，交给你使用的 Agent；复制不会自动安装或授权整理。安装器不会修改 Agent 的目录或系统 PATH。

在程序目录打开 PowerShell，运行 `.\luciddesk-cli.exe status --json` 可检查连接，`help` 可查看命令。详细用法见随包 `cli.md` 或[在线 Agent 指南](https://luciddesk.bbkingdom365.com/agent/)。CLI 支持备份、导出与恢复；使用前通过 `capabilities --json` 检查正在运行的程序支持哪些操作。
