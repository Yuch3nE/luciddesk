# 验证与兼容边界

本页用于选择检查范围、执行实机验收和记录可复现结果，不是某次构建已经通过验证的声明。先运行与修改相关的检查，再按影响补充集成与实机测试；每次提交记录实际执行项，不将历史测试数量或旧测试结果作为当前结论。环境和完整命令见[构建与验证](build.md)。

## 验证层次

| 层次 | 能确认的内容 | 仍需补充的证据 |
| --- | --- | --- |
| 静态与纯逻辑检查 | 编译、类型、模型约束、序列化和调度状态转换 | 原生 API 在目标环境中的行为 |
| 原生集成测试 | COM、窗口、图形、文件和 IPC 路径 | Explorer 实际交互与第三方扩展表现 |
| 离屏渲染与快照 | 几何、裁剪、像素和布局溢出 | 首帧、动画、输入法及真实合成背景 |
| 实际桌面操作 | 选择、拖放、菜单、层级和可见恢复 | 不同系统、DPI、Shell 扩展组合 |
| 安装包生命周期 | 部署、加载位置、升级、卸载与数据保留 | 不同分发渠道和真实新版本替换 |

应用内的原生 UI 单元测试使用 `pane::test_support::apartment()`，并在窗口、模型和渲染器之前声明其返回的 guard。测试进程保留一个 MTA usage 引用，防止不同测试 STA 之间 COM 完全退出、卸载 `Windows.UI.dll` 后，WinRT 激活工厂缓存仍访问旧虚函数表。每个测试仍运行于 STA，guard 先释放线程图形缓存再退出 OLE；不会改动正式程序。实际最终 COM/进程退出测试继续在独立子进程中使用原始 guard，不受该保活机制遮蔽。

原生 COM、图形、菜单和窗口测试需要合适的 Windows 会话。按说明串行或独立进程执行，避免共享桌面、焦点及 STA 生命周期互相影响。单线程测试只能降低干扰，不能让交互测试适用于无桌面的 CI 会话。

| 改动范围 | 重点场景 | 详细入口 |
| --- | --- | --- |

| Shell 菜单 | 鼠标/键盘打开、取消、命令结果、属性及第三方扩展 | [菜单与重命名](pane-item-rename.md) |
| 图形与窗口 | 深浅主题、DPI、首帧、设备失效重建、背压唤醒、缓存变色/释放及层级 | [绘图](rendering.md)、[面板层级](pane-drag-order.md) |

| 托盘 | 延迟分派、菜单、图标重建及正常退出 | [运行时托盘](tray.md) |
| 打包与安装 | 同次构建、标记、快捷方式、更新、卸载及数据 | 下文包验收矩阵 |

交换链像素测试必须在完成绘制后、`end_frame` / `Present` 前调用 `readback`。Flip-model 交换链提交后，0 号缓冲区可能已切换到下一帧，不能把它当作刚刚提交的画面。搜索面板通过 `Drawing::draw_frame` 提供提交前的测试入口，正式绘制仍使用 `paint` 完成绘制和提交。

文档修改通常核对源码、命令和本地链接即可；涉及行为的修改按风险补充测试。测试过滤器必须确认实际命中测试，退出码为零但执行零项不能算行为验证。`--ignored` 只运行被忽略的测试，不能替代默认测试集。

## 常用自动检查

依赖和工具链就绪后，可按范围选用以下命令；`--offline` 要求依赖已缓存：

```powershell
cargo check --workspace --all-targets --locked --offline
cargo test -p luciddesk-core -p luciddesk-storage -p luciddesk-explorer -p luciddesk-shell --lib --locked --offline -- --test-threads=1
cargo test -p luciddesk --bin luciddesk --locked --offline -- --test-threads=1
cargo test -p luciddesk --test canvas_compat --locked --offline
cargo test -p luciddesk-shell --doc --locked --offline
python tools/validation/check-locales.py
```

这些命令不包含默认忽略的交互测试。图形、托盘和 Shell 探针的专用命令见各专题文档；生成绑定变更还需执行生成器的 `--check`。受限桌面、文件占用或工具链缺失造成的失败应记录具体错误，不直接归类为代码回归，也不能视为通过。

当前 Build CI 的检查是本地验收的子集：包含框选纯逻辑、拖动图像透明度及 WARP 彩色 emoji 与 Canvas 离屏测试；框选窗口消息和其他依赖交互桌面的场景仍需本地验收。CI 不自动生成 MSIX。判断某次 CI 的覆盖范围应核对对应提交的工作流和日志。

### 面板性能优化回归

CI 的 `tools/validation/test-control-ci.py` 将排列默认值、固定网格、自由排列、控制布局、延迟任务、排序、行测量和文字缓存测试逐例放入独立进程执行，限制单例 60 秒，避免原生 UI 状态相互影响。每个筛选组必须命中测试，忽略或零用例不能视为通过；筛选逻辑另有 Python 单元测试。可用 `python tools/validation/test-control-ci.py --offline` 在本地复现，添加 `--release` 使用 Release 测试配置。

以下测试验证优化前后的行为约束，不使用耗时阈值判断通过，也不等同于性能基准或全项目覆盖率证明。

| 测试入口 | 覆盖内容 |
| --- | --- |
| `pane::model::performance_tests` | 滚动及真实图片替换复用缓存；改名、增删、重排、坐标、图标大小、网格缩放和排列模式变化后，热缓存与冷测量一致；字体缓存失效；空面板与越界滚动；稀疏网格八个调整方向、负坐标、100%/125%/150%/200% DPI 下按需行测量与完整行测量一致 |
| `pane::label::cache_tests` | 相同输入复用原生文字布局；文字、字体、字号、缩放、宽度、DPI、行数区分缓存；容量上限、替换和最近使用淘汰 |
| `pane::sorting::tests` | 读取前和读取中取消、正常完成及空集合；快照顺序无关但成员变化可检测；已提交的内容或面板变化立即取消任务并释放结果通道；迟到结果不写入；正常排序与重复点击 |
| `pane::render::tests::horizontal_scroll_keeps_preloaded_texture_and_reveals_its_pixels` | WARP 下固定网格/自由排列、多 DPI；横向隐藏仍预加载、滚动不重复上传、进入视口显示真实图片、滚回后像素恢复 |
| `pane::render::tests::scrolling_releases_offscreen_icon_textures` | 纵向滚动后纹理不持续累积，滚回后重新显示 |

先运行定向回归，再串行运行应用完整默认测试集，以发现共享字体、COM 和图形缓存状态的跨用例影响：

```powershell
cargo test -p luciddesk --locked --offline --bin luciddesk -- 'pane::model::performance_tests::' 'pane::sorting::tests::' 'pane::label::cache_tests::' 'horizontal_scroll_keeps' --test-threads=1
cargo test -p luciddesk --locked --offline --bin luciddesk -- --test-threads=1
```

纹理上传计数仅在 `cfg(test)` 中启用；不进入正式构建。取消测试验证停止后续读取，不声称能打断已经阻塞的系统文件调用。混合 DPI 跨屏、真实驱动及网络文件系统阻塞仍需实机验收。

## 实机验收流程

1. 记录源码提交、工作区是否有未提交修改、构建配置和目标架构；准备同次构建的 EXE、桌面 DLL 与符号。
2. 使用隔离数据目录或可恢复的测试数据，记录测试前的配置、布局和已安装版本。会注册正式 MSI 产品身份、安装/卸载或终止进程的工具需先确认影响范围。
3. 执行正常路径，再覆盖取消、重复输入、处理中关闭窗口和失败重试；检查最终文件、配置与窗口状态，不能只看消息发送成功。
4. 退出后检查桌面恢复、Explorer 中的模块及 DLL 文件占用，记录等待时间；主进程已结束不等于桌面组件已释放。
5. 清理测试安装、临时签名信任及测试数据，恢复测试前的运行状态，记录任何未恢复项。

界面验收至少区分深浅主题、最小与常用窗口尺寸、100%/150%/200% DPI。混合 DPI、负坐标屏幕和热插拔必须在对应环境验证，单屏缩放不能代替跨屏操作。设置离屏快照的导出及范围见[设置组件](settings-components.md)。

## 安装包验收矩阵

所有包先核对版本、构建来源、EXE/DLL 配对及 SHA256，再验证运行行为。

| 包类型 | 部署与运行 | 更新与清理 |
| --- | --- | --- |
| 便携版 | `portable` 标记、程序旁 `data`、中文或空格路径、移动目录后运行 | 退出后覆盖真实新版、数据保留、DLL 释放 |
| 安装版 | `installed` 标记、当前用户/所有用户范围、开始菜单快捷方式、卸载记录 | 运行中安装处理、版本替换、修复、卸载清理及数据保留 |
| MSIX | `msix` 标记和真实包身份、WindowsApps 内主程序、缓存 DLL 实际加载路径 | 停止及运行中更新、缓存修复、旧组件占用和卸载清理 |

`tools/validation/test-installer.ps1` 使用随机产品名称和 UpgradeCode 验证 MSI 生命周期；`-AllUsers` 需要管理员会话。夹具不检查真实 Explorer 组件，不代表正式产品的完整桌面生命周期通过。

`tools/validation/test-package-lifecycle.py` 支持 `portable`、`unload` 模式，会启动应用并操作桌面组件，运行前应退出现有 LucidDesk。`tools/validation/test-desktop-sync.ps1` 执行文件夹监听重复回归，并可选运行两项只读桌面探针；每项必须实际执行一个测试，启用真实桌面检查前先阅读脚本的影响范围。这些工具不是纯文档检查的默认步骤。

### MSIX 的必要前提

从普通生产包生成 MSIX，不使用便携包作为输入。安装测试使用受信任签名、实际部署到 WindowsApps 的包；未签名产物只适合相应打包检查，展开目录注册不能代替 WindowsApps 安装验证。构建、身份与签名方法见 [MSIX 打包与运行](../msix.md)。

模式分流需覆盖：标记与包身份同时满足时走包缓存；没有包身份但存在标记时按普通运行方式处理。检查 Explorer 实际加载的 DLL 路径与内容哈希，不能只以应用窗口成功出现判断部署正确。

### 更新场景

| 场景 | 记录与检查 |
| --- | --- |
| 应用已退出 | 新包安装、首次启动、版本、布局与配置保留 |
| 应用运行中普通更新 | 部署结果和错误码；若因占用拒绝，确认原安装仍可用 |
| 强制关闭后更新 | 旧进程结束、组件释放、新包部署及手动启动结果 |
| 新旧 DLL 内容不同 | 新哈希目录被实际使用，旧副本只在可释放时清理 |
| 同一二进制仅提高包版本 | 只能验证部署流程和相同内容缓存复用，不能证明新 DLL 切换成功 |

PowerShell 侧载更新与 App Installer、Microsoft Store 自动更新分开记录。`-ForceTargetApplicationShutdown` 不负责重新启动 LucidDesk，不能把未自动启动判定为应用恢复失败。一次侧载成功也不能证明商店渠道已经验收。

### 异常与缓存恢复

分别测试正常退出、强制终止主进程和可复现的真实崩溃。强制终止可验证控制端消失后的恢复，但不能证明某条异常路径没有问题；主程序崩溃也不能代替 Explorer 内 DLL 崩溃分析。

缓存检查覆盖缺失、损坏、并发部署和旧文件占用，记录修复后的哈希及实际加载路径。卸载时分别检查包注册、LocalState 组件缓存和应用配置数据，不能把 DLL 缓存清理等同于全部用户数据清理。具体数据归属见[存储](storage.md)。

## 平台与兼容边界

- Windows 11 x64 为主要验证和维护平台；其他 Windows 版本的反馈不能代替本次构建在相应版本上的验收。
- 桌面过滤依赖运行期探测的 Shell 视图接口，Win11 精简菜单使用私有 Presenter 接口。系统更新后需要重新检查能力与命令行为。
- ARM64、远程桌面、多显示器热插拔和混合 DPI 需要对应环境，不能由单机启动成功推断完整支持。
- 多语言自动检查覆盖资源与部分布局，译文仍需母语审校；离屏渲染不代表输入法、改名或系统菜单已经验收。
- 第三方 Shell 扩展可能阻塞或改变菜单行为，应记录扩展、目标文件类型及最终命令结果。
- 图形测试需区分硬件路径与 WARP；软件路径通过不能替代目标驱动上的合成、首帧和动画检查。

## 尚待实机验收

多显示器及混合 DPI、另一 Windows 登录会话、已安装 MSIX 的运行与更新、真实显卡设备丢失后的恢复仍需对应环境。单屏离屏测试、WARP 测试和模拟错误注入均不能替代这些验收。

## 结果记录与诊断

每次验收至少记录以下内容：

| 项目 | 需要的信息 |
| --- | --- |
| 产物 | 源码提交、未提交修改、版本、构建配置、架构、包类型与哈希 |
| 环境 | Windows 构建号、显示器/DPI、渲染路径；相关 Shell 扩展或分发渠道 |
| 执行 | 完整命令、实际命中的测试、退出码、操作步骤和测试数据 |
| 结论 | 预期与实际结果、失败证据、未执行或无法覆盖的场景 |
| 清理 | 测试前后安装、数据、信任和运行状态，未恢复项 |

不要将“未执行”“环境阻塞”和“失败”写为通过。延迟或内存比较应保持数据规模、机器、窗口数量和采样方法一致，报告实际测量，不使用调度常量替代性能数据。

崩溃分析保留同次构建的 EXE、DLL 和 PDB；重新构建可能覆盖 `target/production` 中的符号。日志、转储和临时产物留在本地 `target` 或报告附件中，数据与隐私要求见[贡献指南](../../CONTRIBUTING.md)。

诊断包提供 A（当前渲染路径）、B（共享合成树）、C（禁用背景特效）入口，开关与日志见[渲染诊断说明](../../tools/render-diagnostics/RENDER-TEST.md)；崩溃采集与恢复见[崩溃转储说明](../../tools/render-diagnostics/CRASH-DUMPS.md)。这些脚本不随常规便携包分发，诊断变体的结果应标明入口，不能直接当作默认发布路径的结论。

## 0.21.2 回归范围（自正式版 0.20.4）

- 桌面过滤：逐项恢复、存在性未知、操作后核验、坐标警告及保存/订阅独立重试。
- 排序：正式菜单 `dispatch_sort_menu` → `SortPaneColumn`/`SortFolder` → 事件处理器；覆盖右键目标与当前活动页签不同、持久化顺序及回调前释放模型借用。旧 `SortPane` 事件已移除。
- 显示偏好：正式设置事件保存与恢复默认，以及彩色 emoji 和分隔线绘制回归。
- 文件选择：共用 `executable_picker`，覆盖取消、系统错误、文件名校验与 Unicode 路径；此项自动测试不代表人工操作过系统文件对话框。
- 文件夹：失败快照保留、原生枚举属性。
- 可选插件：无 DLL 时不注册监控入口、不创建旧监控窗口；有 DLL 时验证 ABI、设置动作、绘图、采样和退出释放。默认 0.21.2 安装包不含该 DLL。

这些自动回归不能证明 Windows 11 26H2 的所有构建及 Shell 扩展组合均兼容；仍需记录实际 Windows Build 和原生桌面实机结果。

### CI 插件验证与编译复用

`tools/validation/test-plugins.ps1` 从 Cargo JSON 构建产物中取得测试 EXE，编译一次后直接运行有、无插件两轮测试，避免第二轮重新调用 Cargo。测试筛选限定为监控适配器、设置页和插件加载器，每个筛选组必须实际存在；不再通过 `monitor` 模糊匹配显示器测试。窗口几何等测试保留在普通宿主与独立进程控制测试中。

Windows GUI 子系统的测试 EXE 通过 PowerShell 管道同步等待退出，再检查返回码；两轮之间先确保进程结束再移动 DLL。CI 在其他宿主测试结束后执行插件验证。CLI、协议、核心、存储和诊断测试合并一次 Cargo 调用，共享依赖构建；文档测试仍由 workspace doctest 步骤统一执行。调试测试和生产包继续使用独立 target 目录，发布触发条件、安装包种类和默认不含插件的约定不变。

### 监控子进程生命周期与内存

在交互桌面运行 `./tools/validation/test-monitor-process.ps1 -Offline`：构建实际 EXE 与诊断 DLL，先暖机普通窗口，再开关单个监控窗口 10 次（首次 63 秒，其余 2.2 秒）。测试窗口关闭、设置禁用、紧凑布局回传、主进程管道断开，以及无效输入后的禁用与重新启用；断言子进程正常退出、HWND 消失、主进程没有监控采样或绘图实例。输出各阶段私有内存、工作集、句柄与 GDI/USER 资源到 `target/review-validation/monitor-process-memory.log`。脚本结束恢复普通 DLL，不触碰已安装程序，不清空工作集或卸载 DLL。
