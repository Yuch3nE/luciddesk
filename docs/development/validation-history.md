### CI 插件验证与编译复用

`tools/validation/test-plugins.ps1` 从 Cargo JSON 构建产物中取得测试 EXE，编译一次后直接运行有、无插件两轮测试，避免第二轮重新调用 Cargo。测试筛选限定为监控适配器、设置页和插件加载器，每个筛选组必须实际存在；不再通过 `monitor` 模糊匹配显示器测试。窗口几何等测试保留在普通宿主与独立进程控制测试中。

Windows GUI 子系统的测试 EXE 通过 PowerShell 管道同步等待退出，再检查返回码；两轮之间先确保进程结束再移动 DLL。CI 在其他宿主测试结束后执行插件验证。CLI、协议、核心、存储和诊断测试合并一次 Cargo 调用，共享依赖构建；文档测试仍由 workspace doctest 步骤统一执行。调试测试和生产包继续使用独立 target 目录，发布触发条件、安装包种类和默认不含插件的约定不变。

### 监控子进程生命周期与内存

在交互桌面运行 `./tools/validation/test-monitor-process.ps1 -Offline`：构建实际 EXE 与诊断 DLL，先暖机普通窗口，再开关单个监控窗口 10 次（首次 63 秒，其余 2.2 秒）。测试窗口关闭、设置禁用、紧凑布局回传、主进程管道断开，以及无效输入后的禁用与重新启用；断言子进程正常退出、HWND 消失、主进程没有监控采样或绘图实例。输出各阶段私有内存、工作集、句柄与 GDI/USER 资源到 `target/review-validation/monitor-process-memory.log`。脚本结束恢复普通 DLL，不触碰已安装程序，不清空工作集或卸载 DLL。

## Explorer 重启与握手超时（2026-10-20）

握手等待中的消息回调可能打开断线提示框，超过 3 秒后才返回；Explorer 可以在此期间完成连接。等待循环现在先检查桌面身份和 OWNER/ERROR，再判断期限，避免把已经完成的握手误报为超时。保留原有 3 秒期限及重连退避，不新增排队或重试机制。

`attach_observes_result_after_a_callback_crosses_the_deadline` 使用真实 HWND 和计时器回调覆盖迟到成功、迟到错误、桌面被替换及无确认超时。恢复旧循环条件时该测试失败，修复后通过。验证日志位于 `target/control-polish/reconnect-{before,after}.log`，不入库。

用户日志中的 `Ready(28)` 后握手超时与此边界缺陷吻合，但不能据此断言所有重连失败原因相同。最新安装版 PID 94960 的日志另有 Inventory 错误；随后只读 CLI 查询确认 `desktop_connected=true`、`desktop_sync_status=applied`，连接的 Explorer PID 为 38876。布局快照每次重新创建 ShellWindows；本次未定位到该 Inventory 错误的具体 COM 调用，不将其宣称为已修复。错误日志没有后续错误也不等于仍未恢复，应查询实时状态。断线提示框是静态提示，不随恢复刷新。

本轮没有替换安装版，也没有对修复版执行完整的 Explorer 重启验收；原生计时器回归不等同于完整实机重启验证。

## 错误提示统一（2026-10-20）

保留原生 MessageBox，不引入统一等待时间。公共展示入口位于 `luciddesk-window::show_message`，应用文案和日志入口为 `app/src/error_report.rs`。操作失败、桌面连接警告和备份信息分别使用错误、警告、信息图标；七种语言均提供标题、空错误兜底和 Ctrl+C 复制提示。完整路径、错误码和详情保留，嵌入 NUL 转为可见字符，避免截断后续文本。

设置、文件操作、搜索操作和重命名传入发起 HWND；无效或其他进程的 HWND 不作为 owner。后台托盘及桌面断线继续使用无 owner 提示。只有同一 owner、标题、内容和级别的提示正在显示时才抑制嵌套重复；关闭后再次失败仍显示，不设置冷却时间。事件错误仍延后到回调返回，避免借用重入；恢复/删除备份的确认对话框不改为普通错误提示。

搜索加载、文件夹读取和自动备份继续使用已有就地状态。主程序早期初始化失败进入统一错误提示，监控子进程继续通过 IPC 回报，避免后台子进程弹窗。Shell 命令及重命名仅将明确的 `HRESULT_FROM_WIN32(ERROR_CANCELLED)` 当作取消；`E_ABORT`、权限错误和未知错误原样保留。

验证：公共窗口模块 2 项、明确取消处理 1 项；应用语言 3 项、设置 31 项、搜索 16 项、运行时 8 项、重命名 3 项通过。原有事件回调错误测试及新增真实 owner 对话框测试各 1 项通过，验证原生模态回调期间的去重、owner 禁用/恢复、关闭后再次提示和回调借用释放。记录位于 `target/control-polish/error-*.log`。原生测试使用隔离窗口与配置，未替换安装版；没有逐一人工触发所有第三方 Shell 扩展的错误。

### 日志系统可靠性与诊断收集

本轮只优化日志，不改动桌面快照审计调度。内存和文件共享同一个记录（序号、时间、构建信息、线程和真实调用位置），按条数及内容字节数限制事件/错误保留与文件去重缓存；相同来源的重复错误合并次数，ERROR 历史独立于普通日志。文件按严重性分配限额，I/O 失败与退避保留原 OS 错误并正确返回失败，实际写入成功才清除状态。健康报告包括写入、抑制、限流和 I/O 故障数据。可选系统报告回调在日志锁外执行，重入和回调 panic 不影响原始记录；程序入口显式安装保留原 hook 的 Rust panic 堆栈记录。源码位置、原始错误和 HRESULT 不通过业务包装函数传递。

复制诊断先获取只读状态快照并释放应用借用，再查询原生信息和读取当前/上一份文件；快照可在应用状态释放后独立生成报告。不存在的日志文件与实际读取失败分别表示，保留截断和编码错误说明。桌面连接事件只在应用借用之外记录一次，通知去重与日志去重各自处理。具体约定见 [日志与诊断](logging.md)。

日志库 12 项单元测试与 4 项独立进程集成测试通过，日志库所有目标严格 Clippy（`-D warnings`）通过；主程序诊断报告 6 项、运行时 9 项、桌面同步 38 项、设置 50 项，共计 119 项通过，5 项原有交互测试忽略。覆盖回调查询/重入、回调 panic 隔离、8 线程压力、文件/内存相同事件身份、严重性额度隔离、原 OS 错误与退避恢复、字节上限、超长字段及堆栈记录。结果日志为 `target/control-polish/logging-*.log`。Debug 程序构建通过：`target/issue3-focus/debug/luciddesk-logging.exe`。

首次启动验证因已有旧版运行而受单实例保护提前结束（隔离目录 `target/startup-diagnostics/87798c63-e7d5-422d-b2eb-b5f22d80fbf6`），脚本已明确区分该情形与启动崩溃。获得用户明确允许后，核验旧版路径并向其托盘窗口发送正常关闭消息，旧版退出码 0；随后使用隔离空数据库验证新版真实启动、Hook 连接、后台线程启动、进入托盘与正常退出，均通过。验证目录为 `target/startup-diagnostics/76e9cf1b-beb1-4b79-a706-dfc11638b065`；无 ERROR 或 panic 输出，stderr 为空，启动记录包含事件序号、线程、源码位置与当前构建元数据。未强制终止旧版，未使用用户配置或操作剪贴板。


### 日志可读时间与字段分组

日志事件、首次发生时间及报告生成时间统一采用电脑本地日期时间，包含毫秒和 UTC 偏移，不写死系统时区。Windows 从同一个系统时间瞬间使用系统时区/夏令时规则转换，本地日期与偏移一致；不修改或联网校准电脑时钟。事件头采用 `[2026-10-20 21:52:40.763 +08:00]`，主要消息、源码、运行与构建字段以分隔符分组，相对耗时使用毫秒。新进程首次实际写入时追加带可读时间的 v2 会话头，旧记录保留而不改写。事件序号继续用于调整系统时间后的顺序关联。
