# 选择与刷新时序

本文说明面板与原生桌面的选择如何互斥，以及后台清单、成员归属和过滤名单如何保持一致。调度器的唤醒方式见[后台调度](event-driven-runtime.md)，成员过滤协议与恢复边界见[原生桌面与成员过滤](hybrid-desktop.md)。文中的时间均为代码调度参数，不是性能测量或完成期限。

## 实现入口

| 入口 | 职责 |
| --- | --- |
| `app/src/pane/hybrid/mod.rs` | 输入排序、清单消费、持久化与过滤发布 |
| `app/src/pane/hybrid/audit.rs` | 常驻 STA 工作者、单个在途请求及断线重建 |
| `app/src/pane/hybrid/audit_schedule.rs` | 审计退避与变化通知保留 |
| `app/src/pane/hybrid/inventory.rs` | 成员修订键、完整快照和独立来源合并 |
| `app/src/pane/hybrid/icons.rs` | 图标加载、刷新与迟到结果处理 |
| `crates/luciddesk-explorer/src/filter/client.rs` | 选择清理、过滤提交与确认轮询 |

## 双向选择互斥

### 面板输入清除原生桌面选择

`clear_desktop_selection` 记录最近一次面板输入的 `GetMessageTime`。在没有活动菜单、也没有成员同步在途时，通过 `FilterSession::clear_selection` 请求清除原生桌面的选择与焦点，并等待 IPC 处理结果。

获得焦点时已有选中项的分组，通过窗口的 `post_action` 排队触发此操作，不在 `WM_SETFOCUS` 回调内等待 Explorer。焦点消息可能由 Explorer 同步发送，回调内等待其排队工作会导致循环等待。排队操作执行前重新检查焦点和选中项；已经失焦或清空选择时跳过，窗口销毁时取消。新建窗口的选择为空，因此重启后暂时不触发这条路径不能单独证明旧会话已损坏。

每次获得或失去焦点都会更新代次，旧代次的排队操作失效，避免快速切换后重复同步。Shell 嵌套消息循环若在已有面板事件执行期间分派焦点任务，该任务不重入事件回调；当前事件继续负责本轮选择或菜单处理。

时间记录发生在条件检查之前。因此，即使本次受菜单或成员同步阻挡，没有发送清理请求，仍会用本次输入时间保护面板的新选择。这个入口并未为被跳过的清理请求建立独立重试队列，不能将其描述为必然立即完成的互斥操作。

### 原生桌面输入清除面板选择

Hook 的桌面输入通知携带桌面 HWND 和事件时间。接收端核验 HWND，再与最近的面板输入比较：

- 仅接受比面板输入更新的事件；相同时间戳保守地保留面板选择。
- 比较使用 32 位回绕差值，不以窗口前台激活顺序判断先后。
- 活动菜单期间或过时的通知不清除面板选择。
- 应用状态暂时不可借用时保留待处理通知；单个窗口模型不能可变借用时，也保留通知供后续 tick 重试。

清理遍历当前窗口模型，清空选择并取消焦点，只让实际变化的窗口重绘。该路径不逐一遍历后台标签缓存；不要将其扩大表述为清空所有缓存模型。

### 菜单、预览与改名

独立 Shell 菜单使用自身的选中集合。活动菜单、预览和改名事务通过会话状态暂停常规清单消费与过滤同步，避免正在操作的身份被后台结果覆盖。成员同步在途时，`begin_item_menu` 会拒绝开始菜单操作；不允许同时打开另一项菜单或预览。

这里暂停的是控制端的常规处理路径，不表示已经启动的后台枚举被取消。具体菜单和改名提交顺序见[图标菜单与重命名](pane-item-rename.md)。

## 后台清单从读取到接收

1. Shell 变化使审计失效并唤醒控制端；没有通知时按退避期限兜底检查。
2. `DesktopAudit` 最多允许一个在途请求。发送时构造成员身份和修订键，工作者在自己的 STA 中读取。
3. 工作者比较原生视图修订、独立桌面来源修订和成员键。未变化且未强制读取时返回无新快照，否则获取完整元数据。
4. 控制端接收时重新核对成员修订键，仅接受仍适用于当前归属的结果。
5. 接受变化后协调工作区、保存并刷新窗口，再按当前成员及图像状态发布过滤名单。保存失败保留待保存状态，后续重试不会因快照已相等而漏掉保存和展示。

审计请求或结果处理时才构造完整成员身份集合，不在每次普通 tick 中复制和格式化。

### 快照完整性与过时结果

原生桌面视图已被过滤，不能单凭其可见项目判断分组成员是否删除。清单将可见项目与独立桌面来源中仍存在的已收纳成员合并。不完整快照、重复稳定身份或枚举错误会使本次读取失败，不作为成功的空清单或删除结果提交。

成员修订键同时包含稳定身份和 Shell 解析名。重命名后即使文件 ID 不变，也会拒绝旧路径结果。成员归属变化还会标记丢弃当前在途审计；即使拖出后又拖回、最终成员键相同，也不能接受操作前的旧快照。

成员过滤仍在途，或发布缓存失效时，暂缓审计提交与消费。读取期间新到达的变化通知保留到下一次请求发送，不会因消费旧结果而被清除。工作者通道断开后安排重建，下一次强制捕获；重建失败仍保留重试需求。

## 过滤名单的提交与确认

完整过滤名单只包含已有图像的分组成员，避免面板尚未能显示项目时就将其从原生桌面隐藏。名单排序、去重后与发布缓存比较；没有变化时不重复提交。

`submit_hidden` 提交与 `poll_hidden` 确认是两个阶段：

| 状态 | 控制端行为 |
| --- | --- |
| 名单变化 | 发送前使发布缓存失效，提交后记录名单并设置 `membership_pending` |
| 确认未完成 | 保留在途状态，稍后继续轮询，暂缓清单消费 |
| 确认成功 | 清除在途状态，使审计失效以重新核对桌面 |
| 提交或确认失败 | 使相关发布状态失效，标脏并安排后续同步 |

发布缓存记录已提交名单，不等于 Hook 已完成确认。IPC 报错或超时也不代表 Explorer 未接受请求，因此恢复到旧名单时仍可能需要重新发布，不能因缓存相等而跳过。

同步路径还会清理不再属于当前成员的图标失败重试记录，并安排缺失图标加载；这一步不要求刚提交的名单已获确认。图标初次加载和刷新结果按当前成员集合接收，相同像素不替换共享图像。闲置图像预算和淘汰规则见[图标内存管理](memory-optimization.md)。

## 调度参数与延迟边界

| 参数 | 当前行为 | 不代表什么 |
| --- | --- | --- |
| 审计退避 | 初始 2 秒，无变化后依次 4、8、16、30 秒，上限 30 秒 | 每次变化都会等待 30 秒 |
| 变化通知 | 立即使审计到期，保留在途期间到达的新通知 | 能中断当前 Shell 枚举 |
| 同步错误重试 | 保留状态，约 250 ms 后重试 | 所有错误都可在 250 ms 内恢复 |
| 控制端短期唤醒 | 待处理工作通常请求 25 ms 后检查；tick 内另有 20 ms 合并判断 | 固定刷新帧率或端到端响应时间 |
| Hook 维护 | 列表变化触发重滤，一秒定时器补查遗漏变化并检测控制端存活 | 控制端完整清单每秒重新枚举 |

通知缺失时，稳定空闲状态可能等待接近 30 秒才开始下一次兜底审计，还需加上枚举、消息调度、成员确认和可能的重试时间。菜单暂停或 Shell 阻塞会进一步延迟处理，因此不能将 30 秒当成严格的可见更新上限。

## 验证

先按[构建与验证](build.md)准备 Windows 环境。以下测试验证时间排序、退避、结果丢弃、清单合并及发布恢复逻辑：

```powershell
cargo test -p luciddesk --bin luciddesk desktop_input_order_preserves_newer_pane_selection --locked --offline
cargo test -p luciddesk --bin luciddesk pane::hybrid::audit_schedule::tests --locked --offline
cargo test -p luciddesk --bin luciddesk pane::hybrid::audit::tests --locked --offline
cargo test -p luciddesk --bin luciddesk pane::hybrid::inventory::tests --locked --offline
cargo test -p luciddesk --bin luciddesk timed_out_collection_republishes_rollback_after_partial_or_late_hiding --locked --offline
cargo test -p luciddesk --bin luciddesk failed_inventory_save_remains_pending_until_persisted_and_presented --locked --offline
```

实机检查应覆盖：

- 快速交替点击面板和原生桌面，确认较新的选择不会被迟到通知清除。
- 打开和取消菜单、预览及重命名，确认恢复后继续同步，没有覆盖已提交的新身份。
- 后台读取期间拖入、拖出再拖回项目，确认旧结果不会恢复旧归属。
- 在分组中重命名、删除项目，并修改未收纳的桌面项目，检查最终清单与实际来源一致。
- 大量项目或慢 Shell 扩展场景下，分别记录输入发生、清单接收、过滤提交、确认及可见刷新时间。

自动测试通过不能替代 Explorer 中的实际输入与绘制检查。记录 Windows 版本、硬件、项目数量、菜单状态和操作步骤，分别报告选择响应与成员刷新延迟，不用退避常量代替性能数据。完整验收边界见[验证与兼容边界](validation.md)。
