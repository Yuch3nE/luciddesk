# 日志与诊断

应用、Shell、窗口与插件宿主共用 `luciddesk-diagnostics`。日志不修改工作区，不包装业务调用，不改变返回错误、HRESULT 或重试策略。这里不涉及桌面快照审计调度或用户操作审计。

## 使用与排查

设置中的诊断日志级别对应 `config.toml`：

```toml
[diagnostics]
level = "error"
```

支持 `error`、`warn`、`info`、`debug`、`trace`，默认为 `error`。文件位于当前数据目录的 `logs/diagnostic.log`，上一份为 `logs/diagnostic.previous.log`。正常运行不需要开启详细日志；需要复现交互问题时可临时提高级别。错误日志默认也可能创建文件，不要求使用特殊诊断构建。

“设置 → 关于 → 复制诊断信息”汇总系统与构建信息、当时的桌面连接状态、原生 Hook 信息、近期记录、文件输出健康状态，以及当前和上一份日志。收集顺序为获取只读状态快照、释放应用借用、再查询原生信息和读取文件。不同来源并非原子快照；记录中的进程 ID、事件序号和时间可用于关联。

每条标准记录以电脑本地日期时间开头，格式为 `2026-10-20 17:55:10.123 +08:00`，跟随当前系统时区和夏令时；不固定北京时间，也不把 Unix 时间戳作为阅读入口。重复事件的首次时间和诊断报告生成时间使用相同格式。记录同时包含级别、组件/操作、原始消息、进程 ID、构建版本、进程内序号、毫秒相对时间、线程 ID/名称及源码文件/行/列。主要消息、源码位置、线程与构建信息使用 ` | ` 分组。同一条记录用于内存与文件，方便对照；采集时保留当时的时区偏移，之后更改电脑时区也不会改写历史时间。每次进程首次写入时追加带可读时间的 `luciddesk-log-v2` 会话头，旧日志继续保留，便于区分时间格式与构建来源。消息和元数据以转义形式写在单行，中文、换行、控制字符和原始错误码均不会伪造后续日志行。

例如（内容示例）：

```text
[2026-10-20 17:55:10.123 +08:00] level=ERROR component="desktop.hook.attach" message="LoadLibraryExW: HRESULT=0x80070005" | source="app/src/pane/hybrid/mod.rs:400:9" | sequence=42 elapsed_ms=1234 pid=1234 thread=ThreadId(1) thread_name="main" | version="0.21.2" build="example"
```

电脑时间不正确时，应修正操作系统的时间设置；日志本身不连接时间服务器或修改系统时钟。

Rust panic 会记录异常位置、原始载荷和堆栈，并继续执行原有 panic hook 与展开/终止策略。入口由主程序显式安装，依赖库和注入 Explorer 的 DLL 不会自行替换宿主 hook。日志无法保证捕获访问冲突、断电、强制终止或进程已经无法写入的故障；此类原生崩溃仍使用现有转储工具。

## Win+D 面板消失诊断

将诊断日志级别设为 `info` 并退出重启应用后，每个面板每 500 ms 只读采样一次，仅在状态变化时记录 `pane.desktop_state`；默认 `error` 级别不创建采样计时器、不查询窗口状态。采样不调用激活、显示、层级调整或桌面切换 API。销毁面板或降低日志级别时清理计时器和缓存；重新开启采样需再次重启应用。

记录面板及 owner、图标视图宿主、Shell、前台窗口的句柄和类名、可见/最小化状态、DWM cloak 标志、窗口样式，以及面板上方最多 12 个可见窗口和沿 GetWindow 遍历实际 Z 顺序得到的完整排名。不会读取其他窗口的标题或内容。`cloak=0` 表示没有 cloak，位 `1/2/4` 分别表示应用/Shell/owner 继承；查询失败记录 HRESULT，不能当作未隐藏。rank 越小越靠前，`None` 表示未找到，`window_count` 记录遍历数量，`enumeration_ok` 记录是否完整遍历且没有遇到重复句柄（旧版 `scan_truncated=true` 表示达到 512 个窗口上限）。可见且未最小化、未 cloak 不代表没有被遮挡，须同时看宿主和窗口层级。500 ms 采样不能证明期间没有短暂变化。

托盘/快捷键“显示所有面板”额外记录请求、每个面板恢复前后快照、`SetWindowPos` 结果和操作前后的前台窗口。`ShowWindow` 返回值表示此前可见性。沿用已有日志文件轮转与限流，复现后应及时导出。

先启用 `info`，从托盘退出并重新启动应用，关闭设置窗口，等 3 秒。按 Win+D 后等 3 秒。若面板消失，先点托盘“显示所有面板”再等 3 秒，然后打开一个普通窗口并等 3 秒。最后在“设置 → 关于 → 复制诊断信息”导出，并注明每一步的显示结果。打开设置会改变桌面状态，请先记录面板消失时的表现。

## 保留、去重与故障

- 近期事件最多 128 个不同记录、256 KiB 内容；严重错误另保留最多 16 个、128 KiB 内容。相同级别、组件、调用位置和消息合并计数，保留首次序号/时间与最后一条记录，避免重复错误挤掉其他原因。恢复不会清空错误历史。容量淘汰与合并次数明确列入报告。
- 内存记录使用共享引用，快照只在锁内复制引用，格式化在锁外完成。文件去重缓存也受 64 条、256 KiB 内容限制。条目结构和字符串分配另有有界开销。
- 每份文件最多 256 KiB，保留当前与上一份。消息最多 16384 个字符，组件、版本等字段及报告头也有限制，超长内容标注截断与省略字节数。复制每个文件最多末尾 256 KiB；文件不存在、读取失败、部分记录及无效 UTF-8 分别标示。
- 文件内相同事件在 30 秒窗口中合并，该事件下一次实际写入时携带抑制次数。每 30 秒 ERROR、WARN、INFO/DEBUG/TRACE 分别最多写 64 条，普通日志风暴不会耗尽错误额度。限流、抑制和实际写入次数在报告中可见。
- 文件写入失败后保留原始系统错误，5 秒内不重复尝试磁盘写入；`try_log` 在退避期继续返回该错误，不虚报保存成功。下一次可写入事件成功后才清除故障状态。没有后台刷新或重试计时器；标准错误回退同样限制频率。
- 可选系统报告回调在文件锁外调用，重入记录仍保留在内存，并明确返回文件写入不可用；回调 panic 被隔离。panic 中若写入锁忙，会保留内存记录并回退，避免等待文件锁。已完成日志初始化后，内存和文件均携带真实构建元数据。

## 接入约定

宿主调用 `initialize` 选择数据目录和构建信息；库只发送日志。保持消息中的原始错误和具体 API，不据错误码猜测环境原因。在失败边界使用 `inspect_err` 观察错误即可，不用诊断函数执行或包装业务操作。

`log` / `try_log` 先捕获内存记录，再按所选级别处理文件。`emit!` 与 `enabled` 保留惰性过滤：不满足级别时连格式化参数都不会求值，因此被过滤的 `emit!` 也不会进入内存。常规低成本、关键上下文可用 `log`；枚举、图形状态等昂贵调试信息继续使用惰性过滤。

`TraceFile` 仍是显式开启、独立于全局级别和路径的有界支持追踪；调用方选择路径和最大事件数，沿用统一格式和真实调用位置。它不自动开启或上传。

日志仅保存在本地，复制与分享由用户发起。原始错误和 panic 堆栈可能包含个人路径、文件名或插件消息，分享前应检查内容。

## 验证

桌面层级修复单独跟踪图标宿主 HWND。Win10 普通面板的 `native_owner=0x0` 是预期结果，Win11 普通面板和搜索面板使用 Shell owner。判断遮挡应比较 pane 与 icon_host 的排名。`repair blocked` 表示宿主位于面板上方，且中间有普通应用。

INFO 级别的 `pane.desktop_content` 补充记录面板内容透明度：`surface_opacity` 是合成 Surface 缓存的已提交值，`transition_opacity` 是显示动画状态，不是对屏幕最终像素的测量。状态变化及 `WM_SHOWWINDOW`、`WM_WINDOWPOSCHANGED` 时记录；`pane.desktop_state` 的 `content` 附带最近记录值。它用于区分 HWND 可见但内容透明与合成画面未恢复，不能仅凭值为 1 证明画面已正确显示。

`cargo test -p luciddesk-diagnostics --locked --offline` 覆盖字段转义、去重、字节/条数上限、严重性额度隔离、轮转、真实 I/O 失败/退避/恢复、多线程捕获、回调重入及 panic 记录。`cargo clippy -p luciddesk-diagnostics --all-targets --locked --offline -- -D warnings` 检查日志库。

主程序报告回归验证原始错误不变、日志无需借用应用状态、快照可独立存活及文件内容。`tools/validation/test-startup-diagnostics.py` 在正常 Windows 桌面上使用隔离空数据库，验证真实启动、进入托盘和正常退出，不修改用户配置或剪贴板。

桌面排序恢复日志的 `showing_desktop` 区分当前图标宿主是否处于前台。新版同步和只读采样沿实际 Z 顺序遍历，而不依赖 EnumWindows 回调顺序，并以重复句柄检测避免窗口变动引起的循环。

Win11 注册 Win+D 焦点交接 hook 失败时记录 `pane.desktop_owner` 警告。
