# 事件驱动的后台调度

后台工作由变化通知和待办期限共同驱动：通知让任务尽快得到处理，期限负责重试、延迟确认和遗漏通知的兜底。本文说明调度规则；成员过滤的数据流见[原生桌面与成员过滤](hybrid-desktop.md)。

## 实现入口与职责

| 入口 | 职责 |
| --- | --- |
| `app/src/pane/runtime.rs` | 监控窗口、通知消费、重连与最近期限选择 |
| `app/src/pane/wake.rs` | 后台结果和变化通知的 UI 唤醒 |
| `app/src/pane/hybrid/mod.rs` | 桌面同步、在途确认及图标相关期限 |
| `app/src/pane/hybrid/audit_schedule.rs` | 清单审计退避和通知失效状态 |
| `app/src/pane/display_layout.rs`、`recovery.rs` | 显示布局稳定窗口、备份期限 |
| `app/src/pane/auto_hide.rs` | 鼠标状态转换的延迟确认 |
| `crates/luciddesk-explorer/src/filter/menu/worker.rs` | Explorer 菜单 STA 的请求、消息等待与退出唤醒 |

表中的 `recovery.rs` 位于 `app/src/pane/`。主程序的 Runtime、面板窗口和 Explorer 内的工作线程各自处理所属消息；它们不共用一个全局计时器。

## Runtime 的一次调度

1. Shell、后台结果、配置写入或窗口生命周期事件投递通知；显示、DPI、系统设置及电源消息标记相应待办。
2. 监控窗口在能借用 `PaneApp` 时停止上一轮计时器，消费合并通知并处理到期任务。若遇到嵌套回调占用状态，则安排 25 ms 后重试，保留待办。
3. `next_work` 汇总桌面任务、维护、重连、显示布局、备份和热键重试期限，选择最近一项。
4. 复用 Runtime 的计时器安排下一次处理；到期后重新计算，而不是按固定频率执行全部工作。计算出的等待时间至少为 25 ms。

期限是“何时再次检查”的条件，不是严格的响应时间承诺。UI 消息循环、Shell 调用和系统调度都可能推迟实际执行。

## 各类工作的触发方式

| 工作 | 通知与期限 | 无待办时的行为 |
| --- | --- | --- |
| 显示器布局 | 显示、设置、DPI、电源恢复及 `TaskbarCreated` 通知；变化后按两秒稳定窗口重新核对 | 等待后续变化通知 |
| 自动备份 | 成功写入产生合并通知；同时满足静默十秒和配置的备份间隔，后台完成后直接通知 UI | 数据未变化或已有任务执行时不重复启动 |
| 桌面审计 | 变化通知优先；连续无变化按 2、4、8、16、30 秒退避，上限 30 秒 | 等待通知或下一次审计期限；最多一个在途请求 |
| 成员过滤 | 名单变化时发布；在途确认由短间隔调度继续检查 | 名单未变化时不重复发布 |
| 图标加载与回收 | 批次结果、刷新通知、失败重试与最早闲置过期期限 | 没有可执行工作时等待；菜单结束后接续任务 |
| 连接与窗口恢复 | 窗口销毁及任务栏重建主动唤醒；后台就绪探测按 250 ms 起步，退避至两秒，组件连接失败仍最高十秒 | 保留三十秒维护兜底 |
| 显示面板热键 | 配置变化更新注册，冲突按十秒期限重试 | 注册成功后等待输入或配置变化 |
| 自动隐藏 | 鼠标进入、离开、非客户区、位置变化及交互结束重新核对；展开 120 ms、收起 600 ms 确认 | 状态稳定后停止自身计时 |
| Explorer 菜单 STA | 请求入队后设置内核事件，同时等待 Windows 消息；有遗留命令窗口时每秒尝试清理 | 无待清理宿主时无限等待；退出显式唤醒 |

备份期限取“最后变化后十秒”和“上次尝试加配置间隔”中较晚的时间，不是固定每隔几分钟无条件备份。具体持久化行为见[存储](storage.md)。

桌面审计的退避仅限制无变化时的检查频率。变化通知使调度失效并重置间隔；通知缺失时可能等到三十秒审计期限，再加实际处理时间，不能视为立即发现变化。

连接告警与重试调度分开处理：启动或断连后，桌面就绪、组件连接及初始同步失败统一共享三十秒告警等待期。期间记录失败并按既有退避重试，不立即弹窗；持续失败在后续重试中提示一次，连接恢复使排队中的旧提示失效。等待期不会延迟实际连接尝试，也不替代桌面接口检查。

## 通知、在途请求与重入

通知表示需要检查，不表示任务已经完成。审计通知只在真正派发工作时消费；读取期间新到达的通知继续保留，旧结果完成时不能一并清除。结果回到 UI 后仍需校验成员修订，拒绝覆盖新的用户操作。

`submit_hidden` 返回请求已接收，`poll_hidden` 才检查应用结果。成员同步在途时暂缓会冲突的审计消费、选择清除和菜单准备；不在 UI 线程同步等待整批桌面更新。具体顺序见[选择与刷新时序](selection-latency.md)。

配置变更回调只投递消息，不同步重入存储或 `PaneApp`。Shell/COM 对象留在所属线程；菜单工作线程共享持有等待事件句柄，关闭时先将退出请求入队再唤醒，不能在仍有线程等待时关闭句柄。

## 通知送达与工作线程退出

`windows-window` 分派回调时会临时移走处理器。COM 嵌套消息循环可能在此期间取走 `READY`，却没有消费 Wake 的合并标记。`wake::protect_dispatch` 在运行时、搜索及监控控制窗口保留这种通知，等外层回调恢复后补发；CLI 使用 `protect_message_dispatch` 保护自己的队列消息。保护安装幂等，窗口销毁后不补发，仅适用于无载荷、可合并的队列通知。

工作线程应先创建 `Wake::on_drop` 守卫，再将结果发送端移入局部变量，使发送端先析构、守卫后唤醒。这样 UI 能观察到 Disconnected，覆盖正常结束、提前返回及异常展开。接收端必须区分 Empty 与 Disconnected，不能只用 `while let Ok(...)` 丢弃退出状态。

- 搜索断开时结束待完成查询；已接受的成功结果不因随后断开而改成失败。
- 文件夹断开时停止加载并保留已有条目，报告错误；搜索图标清空 pending，保留已缓存图片，缺失图片标记为失败。
- 初始桌面图标批次通过 `InitialCompletion` 交还请求键，即使加载异常展开也能解除批次占用，沿用原有有界重试。
- 监控控制窗口遇到跨窗口状态借用冲突时保留命令，25 ms 后重试；成功消费后停止计时器。

这些机制不取消阻塞中的 Shell/COM 调用，也不新增固定心跳。完成、失败、取消和窗口销毁应分别验证，不能用成功路径替代退出测试。

## 搜索结果内存

Everything 的 `WM_COPYDATA` 回复只在回调期间有效，因此在回调内同步解析为拥有所有权的路径，不再复制完整原始缓冲。解析不调用 Shell/COM；回调返回后不得保留输入切片或指针。

查询工作线程继续合并待处理请求，只执行最新请求。完成结果通道容量为 1；UI 忙碌时最多保留一个排队页和一个生产线程持有的完成页。接收端销毁会解除阻塞发送，线程退出时仍先释放结果通道再唤醒 UI。此限制不丢弃用户已加载的分页结果，也不改变刷新时保留选择与滚动位置的行为。

图标缓存仅保留可见行，上传 GPU 后释放 CPU 像素。这里的内存优化针对临时缓冲和待消费结果，不承诺固定的进程工作集降幅。

## Shell 状态与图标失效

文件操作完成和图标读取分属两层。由应用发起的删除在 Shell 操作返回后协调回收站命名空间状态，包括批量操作部分完成后取消或失败的情况；协调失败只记录诊断，不覆盖原始操作结果。图标加载只读取状态和像素，不打开或刷新 Shell 视图，也不依靠图标是否显示来决定是否处理文件操作的完成。

桌面图标通知通过 `icon_changes` 复制载荷，再在后台解析目标。`SHCNE_UPDATEIMAGE` 的旧式 `SHChangeDWORDAsIDList` 将图像索引放在 `dwItem2`，不能读取通常为零的 `dwItem1`。无载荷、无法解析的项目或暂时失败的图像索引查询不能被视为“没有变化”：前两者保守刷新当前候选集合，后者保留对应候选，由已有图标加载失败重试处理。有效通知仍按项目或图像索引筛选，并沿用合并和延迟调度。

修改通知格式时，应同时运行 `native_image_notification_preserves_system_index` 忽略测试，通过实际 `SHChangeNotify` → Shell 注册窗口消息 → 载荷解析链路验证，而不只构造与实现相同的模拟载荷。该测试会发送真实图像变更通知，应在可交互会话中单独运行。

## 必须保留的恢复机制

- Explorer 内的一秒看门狗负责控制端失联恢复、遗漏重滤和事务重绘解锁，与主程序审计退避独立。
- Runtime 的三十秒维护用于遗漏生命周期通知或窗口创建失败的兜底，不代表每三十秒重建窗口。
- 菜单准备与取消的有界回复等待、动画、目录监听失败重试仍有各自的期限。
- 活动菜单期间暂停的桌面工作要在菜单结束后重新唤醒，不能只停止计时而遗漏恢复入口。

减少空闲工作时应保留这些失败路径，不能仅根据正常通知路径的表现删除兜底机制。

## 修改与验证

新增任务时明确通知来源、在途状态所有者、失败重试期限和退出释放方式；将期限接入所属调度器，避免另开重复轮询。

不依赖原生窗口的审计调度检查：

```powershell
cargo test -p luciddesk --bin luciddesk audit_schedule --locked --offline -- --test-threads=1
```

Runtime 和窗口相关测试在可交互 Windows 会话中运行，环境与隔离要求见[构建与验证](build.md)：

```powershell
cargo test -p luciddesk --bin luciddesk pane::runtime::tests --locked --offline -- --test-threads=1
```

验证应覆盖无变化退避、变化立即失效、在途期间收到新通知、嵌套借用重试、文件夹完成主动唤醒，以及退出时唤醒等待线程。自动隐藏还需实际鼠标操作；记录卡顿时区分通知到达、任务派发、结果返回和 UI 消费时间，避免把某个计时器常量当作性能测量结果。

搜索全局快捷键已移除，不再参与注册、冲突重试或期限计算。托盘“搜索”直接调用 `search::activate`；显示面板热键由 `show_hotkey.rs` 管理。
